# Rust Store and one iroh client path

This decision supersedes ADR 0001's Kotlin state owner, SSH/Phoenix transport and owner-only Unix socket. It preserves the separate Host daemon and long-lived Codex process, ADR 0002's concurrent control, ADR 0003's pairing authorization boundary and ADR 0004's installed-Codex schema adaptation.

`agent-core` owns typed operations, immutable snapshots, a pure reducer and one Store per independent client view or selected mobile Host. Data contains no sockets, locks or callbacks. Only Store performs state transitions and runs effects. Desktop, SwiftUI, Compose and the headless `agent-cli` consume the same snapshots and dispatch typed intents. Core is designed from the behavior corpus; existing UI controllers are not moved into it.

Every client uses iroh, including desktop on the daemon's machine, over ALPN `remote-agent/streams/8` with no fallback wire format. Each RPC opens its own bidirectional QUIC stream carrying Postcard-encoded shared types; there are no wire request IDs, response tables or cross-request ordering waits. A conversation open returns its initial state on the response stream and then carries that subscription's `SessionChange`s on the same stream; dropping the stream ends the subscription. Background notifications use one separate events stream, and item bodies and attachments use their own blob streams. `agent-transport` alone owns iroh endpoints, pairing and stream lifecycle. Its JSONL `RpcPeer` serves only external provider stdio.

A local client is paired during daemon startup using protected identity material. Management operations require the local client's endpoint identity; a remotely paired identity does not gain management access. Invites remain expiring and single-use. Revocation closes live sessions. Secrets use platform secure storage through existing libraries.

The product is unreleased. No protocol-version wrappers, cache migrations or compatibility paths are introduced. Core tests, agent-cli and native client acceptance tests verify the shared implementation.

The 87-case behavior corpus originates at `ea8aefc:crates/agent-client/tests/fixtures/`. Expanded copies retain RPC exchanges, expected outcomes and unknown fields. Its old JSON command tags label scenarios only; they do not define the new public API. Physical iroh adoption was approved following the isolated phone experiment. Cross-platform daemon/UI execution and production mobile behavior require their own verification.

Both private identities occupy one fixed 64-byte owner-only `identity.keys` file. Authorization, invitations and remote profiles are committed atomically to owner-only `trust.json`; blocking storage operations run outside Tokio workers. A mutex orders persistent updates; a failed write leaves the invitation usable and authorization unchanged. A paired remote identity cannot mint invitations, revoke peers or register another Host. Revocation and active-session registration use the same lock order. The client pairs a remote Host using its existing endpoint, then registers the public destination through `host/registerRemote`; no duplicate endpoint or daemon transfer proxy remains.

Daemon project and history transforms use core models. Codex's paginated turn/item envelopes remain boundary types; opaque cursors, opening questions, full image output and on-demand activity details retain their existing behavior. File and settings replacement uses atomicwrites for platform-specific durability, while upload staging uses tempfile. macOS headless checks do not establish Linux, Windows, Keychain or physical-device behavior.

Desktop main, side-chat, terminal and Host-management views dispatch Store intents. Platform adapters own dialogs, recording, protected key access and process launch. Main and side snapshots persist separately per Host and flush before runtime shutdown. The obsolete desktop RPC adapter and conversation state owner are removed.

SwiftUI and Android Compose now own one generated UniFFI `AgentStore` per selected Host. Typed immutable projections reuse Rust identities; neither platform parses wire events or reconciles history. Native adapters retain Keychain/Keystore, media pickers, recording, QR and foreground lifecycle. Snapshot persistence is opaque to native code. Swift flushes atomic files for lifecycle changes, submissions and media edits; ordinary text and stream changes use coalesced writes; Android serializes atomic file writes through its IO owner. Generated bindings remain build outputs. Kotlin common/Native source sets and handwritten FFI bridges are removed together.

Store uses Tokio watch as its canonical snapshot holder. Pure dispatch transitions remain synchronous; watch releases its write lock before waking native observers, so a reentrant observer can read the current snapshot. The effect actor consumes captured snapshots in dispatch order. A deterministic reentrant wake test protects this boundary.

Native observers begin from the last snapshot published to their UI. Reading a newer snapshot as the initial wait cursor can skip connection reads completed between publication and observer startup.

Desktop views borrow one process-owned endpoint and close only their own sessions. A startup mutex covers local daemon provisioning, and the runtime closes the endpoint after view shutdown. GPUI quit hooks await Store closure, PTY termination and final snapshot persistence. Store closure drops snapshot publishers so native waits release their owners. Reconnection clears session-only requests, delivery evidence, watch state and active-work markers. Pending sends remain result-unknown until Host delivery evidence or a native input echo reconciles them; only confirmed non-delivery restores their drafts, without replaying them. iOS foreground return checks Host reachability and storage identity with the paired-client scope read over the existing authenticated session with a one-second recovery deadline. A successful check retains the session and queues selected-conversation, list and model refreshes without making interaction wait for provider reads. Application errors do not trigger reconnection. Disconnected, mismatched or unresponsive sessions are replaced using the retained endpoint. Connection replacement closes the old QUIC session immediately, so an unreachable peer cannot impose the three-second close acknowledgement used by explicit client shutdown; the Host owns connection-scoped PTY and transfer cleanup. Ordinary active reads retain their normal request deadline. iOS snapshot reads, serialization and writes run off MainActor; ordered writes finish before the background flush returns.

The iOS conversation presentation cache is an immutable value projected from the previous cache and current Store snapshot on a detached task. The ViewModel alone replaces the published cache. Android likewise projects an immutable cache from explicit snapshot and previous-cache inputs. It parses only changed Markdown bodies before publishing rows, including offscreen history. One pending input replaces superseded stream updates while a projection runs; Host, navigation and request checks reject obsolete output. Draft dispatch and snapshot publication remain synchronous on MainActor. The composer and file editor share a control-local text buffer; the composer keys it by Host and draft. It updates that buffer before dispatch, so native text cannot regress during a reentrant snapshot notification; every edit still reaches Store synchronously, and external draft changes update the control. Views hold no parser tasks or provisional Markdown rows, avoiding lazy-layout loops as newly visible history obtains its actual height.

Core `Intent` and `Answer` derive UniFFI enums directly; the native boundary has no mirror enum or conversion table. Remote intent variants directly hold the operation record. Each operation has one concrete, owned payload definition with a UniFFI `Record` derive, so the reducer passes it unchanged through `Operation::invalidates` and `prepare`. Rust constructors and generated native defaults supply history flags. `ReadThread` also owns the open-navigation flag, removing the separate `OpenThread` intent. `RpcMethod` serializes wire parameters, while `Operation` owns preparation and state application. Host deserialization owns strings; large audio and terminal byte slices remain borrowed during wire encoding. UI-only flags do not enter RPC parameters, and workflow steps retain separate payloads only when the wire contract differs. Dictation sends its original PCM bytes directly in the request; the Host encodes base64 only for the external speech API. Store has no second intent dispatch table. `run`, `apply` and `stale` also cover approvals, paging, terminal writes, downloads and submission steps; only pairing/registration and attachment upload keep explicit compound execution. Typed payloads and outputs remain in one allocation from the operation queue through ordered completion. `Event` is cloneable serde data with no executable trait object; fixtures replay events or apply typed operation outputs directly.

Store owns connection replacement as well as the attached session. Native adapters validate credentials and bind endpoints, then request reconnection without a separate disconnect. Reconnect closes the previous transport before setup; a newer reconnect, explicit disconnect, Store shutdown or cancellation of the setup future prevents an obsolete candidate from attaching. Session cleanup covers pairing failures and queued candidates discarded during shutdown. Connection-attempt cancellation is runtime resource state, independent of the snapshot epoch used to reject stale view reads. Draft edits remain available during setup, and the same `Connected` transition schedules the reload. Real iroh regressions cover overlapping pairing and replacement, disconnect, shutdown and dropped setup futures; the native binding test covers silent foreground transport recovery and selected-state reload.

`Snapshot.epoch` scopes navigation, workspace and account work. List results and failures instead belong to the requested query, so search and display-limit changes do not invalidate a conversation read and task navigation does not discard a current list. `finish` checks the epoch or query under the publication lock and delegates stale policy to the operation. Store permits one list request at a time and coalesces refreshes into one follow-up using the latest query. Completed sends, file-save revision reconciliation and transcribed drafts retain their effects without restoring the old view. Publication exhaustively destructures Snapshot and tests each field independently, so a new field cannot silently bypass the comparison boundary. `Connected` resets session state and schedules list/model reads plus the selected conversation, or the new-chat workspace review. Zero initial list limits become five in Core; cached search and expansion limits remain intact. Opening a conversation restores its history watch and workspace review. Desktop and mobile do not schedule a second connection reload; CLI initializes its query/navigation before connection and waits for those same reads. Follow-up effects capture their snapshot under the publication lock, so later navigation cannot relabel an old effect with a new epoch. Automatic workspace reviews share the navigation or notification epoch and cannot invalidate concurrent bootstrap reads. Workspace navigation, completed work and completed file-changing activities refresh the review. The generated native boundary verifies reconnection reloads without native dispatch while preserving drafts and rejecting old transport data. Notification handling classifies the method once and separates process, turn and item transitions.

`agent-core::presentation` owns item body formatting, request-to-turn association, request/error labels, pending-input reconciliation and segmented conversation rows for all three clients. GPUI consumes its `RenderedConversation` directly; desktop no longer has a separate `ProjectedTurn` or grouping routine. UniFFI derives records on core leaf values and exposes Snapshot, conversation nodes, rendered nodes and large workspace reviews as shared objects. The `agent-ffi` crate only packages the library and binding generator; it has no duplicate DTOs or projection graph. Arbitrary provider JSON fields, such as tool input, output and errors, use one typed converter at the language boundary. Immutable render objects reuse unchanged turns and items by identity; native caches only marshal rows and parse Markdown. Expanded activity output is formatted on demand. Swift and Kotlin no longer maintain parallel projection rules.

The Host keeps its multi-session request router. Every client sees the same approval ID, built from provider, session, turn and native request ID, with no per-client alias. A conversation open includes the execution's unresolved requests, each outbound queue is bounded, and the first valid response is claimed. `agent-transport::peer` owns JSONL framing, classification and typed response envelopes for provider stdio. `codex-app-server` supplies stdin/stdout to that peer and retains process lifecycle and initialization. Host handlers decode typed parameters and return typed models. Core history and item models own chronological paging and detail deferral. Native project snapshots use core `Project` values; title collection borrows project metadata and clones only the visible result. Host service handlers retain filesystem, worktree and account effects; GPUI view code retains widgets and native input/rendering state.

The iOS observer makes one reconnect attempt when an established connection is lost, unless another attempt is already running. Failure remains visible for manual retry. The reconnect button always replaces the connection, including when an RPC failure left the transport connected, so Core resets the error and reloads the selected conversation. Starting that attempt also clears the native operation notice; drafts remain in the same Store throughout recovery.

Desktop asynchronous adapters return typed updates directly; one UI owner rejects stale Host epochs before applying an update and checks operation-specific navigation or input revisions. Operations without UI completion state dispatch directly and use the existing Store snapshot subscription for their results and errors. They no longer send closures that receive mutable Desktop state. Native conversation components receive immutable display values and actions; connected screen boundaries retain lifecycle ownership. iOS keeps one immutable conversation presentation, including reusable native rows, and computes its successor from the prior value and a Snapshot. There is no separately mutable presentation cache. Asynchronous callers share one Result bridge at the Store owner; file downloads own temporary-file cleanup there, and callback-driven settings screens use completion snapshots directly. Android composer controls emit existing core Intents without per-operation forwarding callbacks in the root. RPC errors remain in the core Snapshot rather than being copied to native notices; successful retries clear core errors while preserving unrelated local failures. `just android-e2e` checks this with a real isolated Host, Store and Android model. Workspace requests return their completion snapshot explicitly so save-conflict handling does not depend on a passed ViewModel. File-editor controls receive a narrow String binding whose getter reads the latest Store draft, and share the composer’s local text buffer. Capturing an older Snapshot in that getter would replay partial keystrokes during reentrant publication.

Host routing transitions consume owned protocol state and produce the next state and deliveries. The router retains its existing lock across transition, nonblocking queue delivery and failed-session cleanup, preserving response arbitration without exposing sockets to the decision functions. A reconnecting client obtains unresolved requests from the next conversation open. Regression checks cover repeated-turn projection, stale Desktop completions, deterministic routing, queue saturation and reconnect response arbitration.

Clients submit an input intent through `host/session/submit`; they no longer choose native start, steer, queue or resume operations from cached conversations. Host serializes submission decisions and provider acknowledgement per conversation, reads current provider state and overlays its owned live execution before choosing the operation through a pure `agent-protocol` function. Conversation snapshots and updates include Host-owned input delivery evidence, alongside unresolved requests. Store caches that evidence and reconciles its local pending input and draft; activity notifications alone update the per-client activity index. Local navigation epochs, operation receipts, history cache, unread state and drafts retain their client-side roles.

The Host keeps bounded delivery evidence for unconfirmed inputs and replays accepted receipts by input ID while retained. A completed turn alone cannot erase an input that is still being delivered or has not been echoed. Evidence can retire when the provider has echoed that input in a finished turn; native history then supplies the input identity during client reconciliation. This is live execution state, not a durable idempotency ledger across Host restarts. Missing evidence never proves non-delivery and never causes automatic resubmission. Snapshot acquisition and live updates continue to use the existing session subscription boundary; transport and connection lifecycle are unchanged by this ownership change.
