# Rust Store and one iroh client path

This decision supersedes ADR 0001's Kotlin state owner, SSH/Phoenix transport and owner-only Unix socket. It preserves the separate Host daemon and long-lived Codex process, ADR 0002's concurrent control, ADR 0003's pairing authorization boundary and ADR 0004's installed-Codex schema adaptation.

`agent-core` owns typed operations, immutable snapshots, a pure reducer and one Store per independent client view or selected mobile Host. Data contains no sockets, locks or callbacks. Only Store performs state transitions and runs effects. Desktop, SwiftUI, Compose and the headless `agent-cli` consume the same snapshots and dispatch typed intents. Core is designed from the behavior corpus; existing UI controllers are not moved into it.

Every client uses iroh, including desktop on the daemon's machine. A session is one bidirectional stream carrying JSONL JSON-RPC. The same transport-independent peer serves Codex stdio, daemon sessions and clients. It exposes one typed request API, one raw request API and one ordered incoming event stream. The transport module alone owns iroh endpoints, pairing and stream lifecycle.

A local client is paired during daemon startup using protected identity material. Management operations require the local client's endpoint identity; a remotely paired identity does not gain management access. Invites remain expiring and single-use. Revocation closes live sessions. Secrets use platform secure storage through existing libraries.

The product is unreleased. No protocol-version wrappers, cache migrations or compatibility paths are introduced. Core tests and agent-cli are the migration gates; legacy UI may be temporarily broken. Core and CLI precede the daemon, desktop and mobile cutovers. Once generated UniFFI bindings are available, Kotlin common and hand-written FFI are removed together.

The 87-case behavior corpus originates at `ea8aefc:crates/agent-client/tests/fixtures/`. Expanded copies retain RPC exchanges, expected outcomes and unknown fields. Its old JSON command tags label scenarios only; they do not define the new public API. Physical iroh adoption was approved following the isolated phone experiment. Cross-platform daemon/UI execution and production mobile behavior require their own verification.

Both private identities occupy one fixed 64-byte keyring entry. Authorization, invitations and remote profiles are committed atomically to owner-only `trust.json`; blocking storage operations run outside Tokio workers. An explicit file backend supports headless servers without silently replacing an unavailable keyring. A mutex orders persistent updates; a failed write leaves the invitation usable and authorization unchanged. A paired remote identity cannot mint invitations, revoke peers or register another Host. Revocation and active-session registration use the same lock order. The client pairs a remote Host using its existing endpoint, then registers the public destination through `host/registerRemote`; no duplicate endpoint or daemon transfer proxy remains.

Daemon project and history transforms use core models. Codex's paginated turn/item envelopes remain boundary types; opaque cursors, opening questions, full image output and on-demand activity details retain their existing behavior. File and settings replacement uses atomicwrites for platform-specific durability, while upload staging uses tempfile. macOS headless checks do not establish Linux, Windows, Keychain or physical-device behavior.

Desktop main, side-chat, terminal and Host-management views dispatch Store intents. Platform adapters own dialogs, recording, protected key access and process launch. Main and side snapshots persist separately per Host and flush before runtime shutdown. The obsolete desktop RPC adapter and conversation state owner are removed.

SwiftUI and Android Compose now own one generated UniFFI `AgentStore` per selected Host. Typed immutable projections reuse Rust identities; neither platform parses wire events or reconciles history. Native adapters retain Keychain/Keystore, media pickers, recording, QR and foreground lifecycle. Snapshot persistence is opaque to native code. Swift flushes atomic files for lifecycle changes, submissions and media edits; ordinary text and stream changes use coalesced writes; Android serializes atomic file writes through its IO owner. Generated bindings remain build outputs. Kotlin common/Native source sets and handwritten FFI bridges are removed together.

Store uses Tokio watch as its canonical snapshot holder. Pure dispatch transitions remain synchronous; watch releases its write lock before waking native observers, so a reentrant observer can read the current snapshot. The effect actor consumes captured snapshots in dispatch order. A deterministic reentrant wake test protects this boundary.

Native observers begin from the last snapshot published to their UI. Reading a newer snapshot as the initial wait cursor can skip connection reads completed between publication and observer startup.

Desktop views borrow one process-owned endpoint and close only their own sessions. A startup mutex covers local daemon provisioning, and the runtime closes the endpoint after view shutdown. GPUI quit hooks await Store closure, PTY termination and final snapshot persistence. Store closure drops snapshot publishers so native waits release their owners. Reconnection clears session-only requests, watch state and active-work markers, and recovers unaccepted pending sends into drafts without replaying them. Mobile foreground return replaces a transport even if its cached connected flag survived suspension. iOS snapshot reads, serialization and writes run off MainActor; ordered writes finish before the background flush returns.

The iOS conversation presentation cache is an actor over immutable Store values. It parses only changed Markdown bodies before publishing rows, including offscreen history. One pending input replaces superseded stream updates while a projection runs; Host, navigation and request checks reject obsolete output. Draft dispatch and snapshot publication remain synchronous on MainActor. The composer holds a control-local editing buffer keyed by Host and draft. It updates that buffer before dispatch, so native text cannot regress during a reentrant snapshot notification; every edit still reaches Store synchronously, and external draft changes update the control. Views hold no parser tasks or provisional Markdown rows, avoiding lazy-layout loops as newly visible history obtains its actual height.

Core `Intent` and `Answer` derive UniFFI enums directly; the native boundary has no mirror enum or conversion table. Remote intent variants directly hold the operation record. Each operation has one concrete, owned payload definition with a UniFFI `Record` derive, so the reducer passes it unchanged through `Operation::invalidates` and `prepare`. Rust constructors and generated native defaults supply history flags. `ReadThread` also owns the open-navigation flag, removing the separate `OpenThread` intent. `RpcMethod` serializes wire parameters, while `Operation` owns preparation and state application. Host deserialization owns strings; large audio and terminal byte slices remain borrowed during wire encoding. UI-only flags do not enter RPC parameters, and workflow steps retain separate payloads only when the wire contract differs. Dictation serializes its original audio as base64 directly into the request. Store has no second intent dispatch table. `run`, `apply` and `stale` also cover approvals, paging, terminal writes, downloads and submission steps; only pairing/registration and attachment upload keep explicit compound execution. Typed payloads and outputs remain in one allocation from the operation queue through ordered completion. `Event` is cloneable serde data with no executable trait object; fixtures replay events or apply typed operation outputs directly.

One `Snapshot.epoch` replaces independent navigation, workspace, account and list generations. `finish` compares it once under the publication lock and delegates stale policy to the operation. Completed sends, file-save revision reconciliation and transcribed drafts retain their effects without restoring the old view. Publication exhaustively destructures Snapshot and tests each field independently, so a new field cannot silently bypass the comparison boundary. `Connected` resets session state and schedules list/model reads plus the selected conversation, or the new-chat workspace review. Zero initial list limits become five in Core; cached search and expansion limits remain intact. Opening a conversation restores its history watch and workspace review. Desktop and mobile do not schedule a second connection reload; CLI initializes its query/navigation before connection and waits for those same reads. Follow-up effects capture their snapshot under the publication lock, so later navigation cannot relabel an old effect with a new epoch. Automatic workspace reviews share the navigation or notification epoch and cannot invalidate concurrent bootstrap reads. Workspace navigation, completed work and completed file-changing activities refresh the review. The generated native boundary verifies reconnection reloads without native dispatch while preserving drafts and rejecting old transport data. Notification handling classifies the method once and separates process, turn and item transitions.

`agent-core::presentation` owns item body formatting, request-to-turn association, request/error labels, pending-input reconciliation and segmented conversation rows for all three clients. GPUI consumes its `RenderedConversation` directly; desktop no longer has a separate `ProjectedTurn` or grouping routine. UniFFI derives records on core leaf values and exposes Snapshot, conversation nodes, rendered nodes and large workspace reviews as shared objects. The `agent-ffi` crate only packages the library and binding generator; it has no duplicate DTOs or projection graph. Unknown JSON fields use one typed converter at the language boundary. Immutable render objects reuse unchanged turns and items by identity; native caches only marshal rows and parse Markdown. Expanded activity output is formatted on demand. Swift and Kotlin no longer maintain parallel projection rules.

The Host keeps its multi-session request router. It assigns a distinct approval ID per client, replays unresolved requests after reconnect, bounds each outbound queue and accepts the first valid response. `agent-core::peer` owns JSONL framing, classification, ID rewriting and typed response envelopes; the separate `host-protocol` crate is removed. `codex-app-server` supplies stdin/stdout to that peer and retains process lifecycle and installed-schema discovery. Host handlers decode serde parameters and return typed models while the peer preserves raw envelope extensions and remote errors. Core history and item models own chronological paging and detail deferral. Desktop project snapshots build core `Project` values once; title collection borrows project metadata and clones only the visible result. Host service handlers retain filesystem, worktree and account effects; GPUI view code retains widgets and native input/rendering state.

The iOS observer makes one reconnect attempt when an established connection is lost, unless another attempt is already running. Failure remains visible for manual retry. The reconnect button always replaces the connection, including when an RPC failure left the transport connected, so Core resets the error and reloads the selected conversation. Starting that attempt also clears the native operation notice; drafts remain in the same Store throughout recovery.
