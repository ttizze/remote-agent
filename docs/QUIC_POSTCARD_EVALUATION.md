# iroh + Postcard の整理

比較元は `9618c7f`。未コミットの作業ツリーを比較する。

## 構造

- 通常の RPC は一要求につき一つの QUIC 双方向ストリーム。ネットワーク上の要求 ID・応答対応表・全要求の順序待ちは使わない。
- 会話の初期状態と更新は同じ応答ストリーム。Store は初期状態を適用してから更新を読む。
- Store は不要になった購読ストリームを破棄する。Host は `SendStream::stopped()` と購読所有者の破棄で登録を解放する。Store の購読終了 RPC と切断時だけ成功扱いにする分岐は削除した。
- `ReadItem` と本文転送は他の要求を待たせない。中間操作 `ResolveItem` は削除した。
- QUIC の要求タイムアウトは当該ストリームだけを終了する。旧 JSONL の受信カウンターによる接続全体の切断判定は使わない。JSONL 送信キューも QUIC 接続では作らない。
- 背景通知は別ストリームを Store が直接読む。Client の受信タスク・broadcast キュー・初回受信用状態・独自の切断トークンは削除し、接続状態は QUIC から取得する。フレームは最大 16 MiB。Host の購読キューも接続単位で 16 MiB を共有する。
- ALPN は `remote-agent/streams/5`。旧ネットワーク形式へのフォールバックはない。

## データ型

共有の Rust 型を通常の Serde derive で Postcard に渡す。要求は既存の引数型を持つ `Call` enum とし、メソッド文字列＋引数バイト列の包み、引数の二重復元、別の FileRequest/AccountRequest への組み直しを削除した。enum と外部 JSON 境界の対応は一つの一覧から定義し、モデルのフィールドは二重定義しない。外部プロバイダーの任意 JSON 要求は専用の Provider variant に限定する。
Host の作成・ファイル・転送・端末・接続先登録も Core の要求型を使う。Claude の内部要求と結果、Codex の履歴・モデル取得も型を直接受け渡す。
型付き通信への移行でテストからしか呼ばれなくなった JSON 中継 API、応答メタデータの保存・再シリアライズ、旧 `turn/start` 応答形式と旧通知形式の変換は削除した。

モデルの未知フィールドを保存する `extra` は廃止した。Bex が使う履歴情報、時刻、ツール情報などだけを明示的なフィールドにする。未知のファイル変更形式も保存しない。
プロジェクト未指定と明示的な所属なしは画面遷移に必要なので、既知の状態として区別する。

Bex の Client はネイティブ QUIC 接続そのものとし、接続を包むだけの Client ラッパーを削除した。要求・応答は共有型を直接 Postcard で渡す。`request_json`、QUIC の `request_raw`、購読更新を背景通知に中継する処理は削除した。`RpcPeer` は外部プロバイダーの JSONL 専用とし、QUIC と JSONL のモード分岐をなくした。メソッドと共有型の対応表は外部プロバイダー境界とテストデータの読込だけに使う。
ツール引数・結果・エラーなど、内容自体が任意の JSON である既知フィールドには短い Serde adapter を使う。

## 残す責任

古い読み取り結果の適用防止、送信の重複防止、購読先、転送許可、認可、並列数上限はアプリケーションの責任として残る。QUIC は切断後の処理結果や exactly-once 実行を保証しない。

購読終了 RPC は削除し、購読ストリームの破棄で終了する。Client の終了処理は戻り値を持たず、Store は終了完了だけを待つ。タスクの異常終了は検出する。短命な CLI の接続終了確認は、終了パケットを送る前にランタイムが消えることを避けるために残す。
通信型のフィールド型・順序や enum の variant 順序の変更は wire format の変更なので、非互換変更では ALPN を更新する。`Thread` のマージ済みフラグを worktree 状態へ変えた際も更新し、旧 Host の `false` が新クライアントの `Unmerged` として復元される接続を拒否する。Host とクライアントは同じリビジョンからビルドして更新する。

## 検証と規模

独自 codec、未知フィールドの保存、廃止した状態表現のテストを削除した。順序、キャンセル、再接続、承認、履歴取得、添付、画面遷移の振る舞いのテストは維持する。サイズ上限の検証は JSON 再表現の長さではなく Postcard の送信サイズで行う。

以下は main のネイティブターミナル変更を統合する前（`ad03f1c`）の比較。新規ファイルも含めて比較する。製品の Rust 本体は比較元より **211 行減少**（空行・コメント込み。fixture・example・末尾のテストモジュールを除く）。テスト込みの Rust 全体は **129 行減少**、設定・文書を含む全変更は **228 行減少**。全て作業ツリー対比較元の差分で、新規ファイルを含む。

テスト専用の JSONL ↔ QUIC 中継、stdio による Bex 接続、旧 JSON 形式の欠落フィールドを検査するテストを削除した。Store の部品テストも製品と同じ Session・Client・Postcard を通す。実際の HostRuntime を使う結合テストは別途維持する。

最終変更後の Clippy（警告をエラー扱い）、関連テスト289件、Host・Desktop・CLI・iOS Simulator向けビルドが通過。実アカウントのClaudeテストと301秒soakの2件は既存のignoreを維持した。実行中の Host は更新・再起動していない。

## 通信経路の変換監査

| 経路 | 最終形と削除した変換 |
| --- | --- |
| 通常の要求・応答 | 共有型 ↔ Postcard。Bex 接続の JSON 形 API を削除した。受信フレームは BytesMut のまま読み、Vec への全コピーをしない。 |
| 初期会話・購読更新 | 初期応答の後は SessionChange だけ。通知種別と購読 ID は送信しない。古い購読を識別する UUID はクライアント内で生成し、Store 内部のイベントとして扱う。 |
| 入力・状態 enum | 入力リスト、会話状態、履歴状態を Postcard で直接表す。入力リストを JSON 文字列で包む処理、状態 enum と String の相互変換、未知の状態名の保存を削除。 |
| Claude | Core の入力型を直接読む。結果の JSON 化と再読込を削除。ライブメッセージと履歴は共通の純粋関数で Item を組み立てる。 |
| Codex | 履歴・モデルは型付き応答。転送する会話は一度だけ型に読み、補完後の JSON 再表現・再読込を削除。通知のパラメーターも再パースせず利用する。 |
| 端末 | Bex 間・Store 内はバイト列。Base64 は JSONL と Desktop の WebView 境界だけ。 |
| 録音 | Bex 間は PCM バイト列。Host の外部音声 API に渡す時だけ Base64 を作る。 |
| 本文・添付転送 | トークンと SHA-256 は固定長配列。可変長文字列の検査と Base64 の相互変換を削除。アップロード完了通知も共有型の Postcard に統一。 |
| 承認・ツール・エラー | 外部仕様の任意 JSON は保持する。型が既知の RPC レコード全体を JSON に包む用途には使わない。 |

残す変換には次の目的がある。

- 外部 Codex / Claude の JSONL と共有型の相互運用。JSON の記録済みテストデータは読込時に型に変換し、通信には Postcard を使う。
- 任意 JSON のツール入力・出力・エラー・プロバイダー ID。Postcard は serde_json::Value を直接復元できないため、このフィールドだけ JSON adapter を使う。
- 外部音声 API、WebView、JSONL の Base64 表現。QUIC 内のバイト列を Base64 にして送るためではない。
- ファイルのリビジョン、チケット、保存データ、画面表示など、通信とは別に文字列表現そのものが必要な境界。

この監査は通信経路とその利用側を対象とする。外部 API の形式変換と、QUIC に渡す前後のシリアライズは必要な責任として残る。
