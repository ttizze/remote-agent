# BexのApp Store審査準備

初回確認日：2026年9月17日。2026年9月21日に統合時のソース差分を確認。ソースコードを確認した段階です。審査通過を確認した文書ではありません。App Store Connectの登録内容、配布用アーカイブ、実機での最終動作は未確認です。

## 提出までに必要なこと

- **プライバシーポリシーと問い合わせ先を公開する。** アプリ内でも、ペアリング前と接続後の両方からポリシーを開けるようにします。現在のソースには、そのリンクが見当たりません。
- **AIへのデータ送信を説明し、送信前に同意を得る。** 対象は入力文、添付ファイル、エージェントが使用する作業ファイル、音声入力です。共有する相手と用途を説明します。共通の判定と保存は `agent-core` が担当し、各アプリはその結果を表示します。
- **審査員が実際に使える環境を用意する。** 現在は初回起動がPCペアリング画面です。下記の環境案を参照してください。
- **価格を決める。** 無料、有料ダウンロード、アプリ内課金のどれにするかに合わせて、説明文と外部サービスのログイン導線を確認します。
- **配布用ビルドのプライバシー申告を確認する。** 追加したPrivacy Manifestは、確認できたUserDefaultsの用途だけを記載しています。Rust・Swiftの依存ライブラリ、必要なAPI申告、収集データの回答まで確認済みという意味ではありません。
- **暗号化の輸出申告を確定する。** フランスでの配信予定と、使用する暗号化の分類を確認してからplistへ設定します。

## 審査用環境の方針

審査のためだけのアプリ内デモは追加せず、実際のBex Hostへの接続で主要機能を確認してもらう方針です。TermiusはSSHクライアント、MoshiはSSH/Mosh経由で利用者のPC上のエージェントを操作するアプリとして公開されています。ただし、両社がAppleに提出した審査用の接続情報や非公開の審査手順までは確認できていません。

サンプル用リポジトリだけを置いた審査専用のPCまたは仮想環境で、実際のBex Hostを動かします。個人の作業PCではなく、ファイルとネットワークの両方で個人環境から隔離します。エージェントの認証は、第三者が操作する審査用途で利用可能かを確認したものだけを使います。

必要な準備：

1. 審査期間中に停止・スリープしない専用環境を確保する。
2. 個人ファイルや本番用の秘密情報を置かず、サンプルデータを復元できるようにする。
3. 再インストールや複数の審査端末でも接続できる招待方式を用意する。
4. 審査メモに接続方法、操作例、必要な外部サービスを記載する。接続用の秘密情報はリポジトリに保存しない。
5. 開発環境の外にある初期状態の端末で、その手順を試す。

現在の招待は既定で7日間有効ですが、一度使用すると消費されます（`host_runtime.rs`、`agent-transport/src/transport.rs`）。複数端末や再インストールの審査に同じQRを使い回すことはできません。審査専用Hostで必要に応じて招待を再発行し、接続手順を維持します。繰り返し使用できる審査用招待は未実装です。

審査環境の稼働先は未決定です。アプリ内に固定接続先を埋め込まず、審査メモから通常のペアリング操作で接続してもらいます。

参考：[Termiusの製品説明](https://termius.com/free-ssh-client-for-iphone)、[Moshiの製品説明](https://getmoshi.app/docs/introduction)。

## フランスと暗号化の質問を毎回出さないための設定

公開先は米国・日本・中国を予定し、フランスは対象外とします（ユーザー指定）。App Store Connectの配信地域はまだ変更していません。中国での提供可否や必要な手続き、現地ネットワークからの実利用は別途確認が必要です。

App Store Connectがビルドごとに聞く暗号化の質問は、`Info.plist` の設定で省略できます。ただし、必要な申告そのものが不要になるわけではありません。

| 確定した申告内容 | plistに設定する内容 |
| --- | --- |
| 暗号化を使わない、または書類提出の免除対象だけを使う | `ITSAppUsesNonExemptEncryption = NO` |
| 免除対象ではない暗号化を使う | `ITSAppUsesNonExemptEncryption = YES`。Appleが書類を承認した後のコードを `ITSEncryptionExportComplianceCode` に設定する |

Bexは `agent-core/Cargo.toml` で `iroh` の `tls-ring` 機能と `ring` を使用しています。そのため「iOSに備わるHTTPSだけを使う」という説明にはできません。Appleの案内では、OS外に実装された標準暗号を使用する場合、フランスで配信するならフランスの暗号化申告書を提出する分類が示されています。最終的な申告は、実際の暗号化用途と免除条件を確認して決めます。

フランスを配信対象から外すだけで、すべての暗号化申告が不要になるとは限りません。配信国はApp Store Connectで設定します。フランスへの配信を止めるplistキーではありません。

書類が必要な場合は、一度提出して承認されたコードをplistへ組み込み、以後のビルドへ引き継ぐ形で自動化します。現時点では分類・承認コードが未確認のため、推測の値や空のコードは追加していません。

## Bex固有の確認事項

- **リモート操作の分類。** ガイドライン4.2.7は、特定のソフトを映すリモートデスクトップにLAN限定などの条件を定めています。Bexは画面転送ではなく独自の会話・ファイル・ターミナルUIなので、該当するかを断定せず構成を説明します。インターネット接続とiOSからの外部アカウントログインも正確に伝えます。
- **コードの実行場所。** エージェントやシェルはPC側で実行します。ただし、アプリは生成された操作可能なHTMLをWebKitでも表示するため、「静的なテキストだけ」とは説明しません。ガイドライン2.5.2との整合を確認します。
- **外部サービスの利用許可。** ガイドライン5.2.2に関係します。特に音声入力は `dictation.rs` で `chatgpt.com/backend-api/transcribe` を使っています。接続できることと、配布アプリでの利用が許可されることは別なので、公開前に確認します。
- **アカウントと削除。** BexのPCペアリングと、外部AIサービスのアカウントを区別します。「PCの接続解除で外部アカウントや会話履歴も削除される」とは説明しません。

## この作業で追加済みの設定

- 同じネットワークのPCに接続する目的を説明する `NSLocalNetworkUsageDescription`。
- アプリ自身の設定保存にUserDefaultsを使う理由 `CA92.1` を記した `PrivacyInfo.xcprivacy`。アプリのリソースとして登録済み。

plistの構文、Xcodeによるプロジェクト読み込み、Privacy Manifestのリソース登録を確認しました。配布用アーカイブへの格納と実機動作は未確認です。

## 審査メモの日本語下書き

Bexは、利用者がペアリングしたPC上のコーディングエージェント、ファイル、ターミナルを操作するアプリです。PCには別途Bex Hostが必要です。エージェントとシェルの処理はiPhoneやiPadではなく、そのPCで実行します。

iOSアプリは結果を独自の会話・ファイル・ターミナル画面に表示します。生成された操作可能なHTMLをWebKitで表示する機能もあります。接続にはローカルネットワークまたはiroh経由のインターネット通信を使います。外部AIサービスの認証はPC側で管理し、iOSからログインを開始することもできます。Bexは独立した製品で、OpenAIやAnthropicの公式アプリではありません。

実際の提出時には、審査用の接続手順、料金、公開済みのポリシーと問い合わせ先、必要な利用許可の情報を追加します。この下書きだけでは提出できません。

## 最後の動作確認と提出作業

1. 対応するiPhoneとiPadで、初回起動、ペアリング、権限拒否、切断と再接続、会話、添付、音声、ファイル、ターミナル、接続解除を確認する。
2. Hostと影響を受けるアプリを同じ版からビルドする。稼働中Hostを再起動する前に、実行ファイルと進行中タスクを確認する。
3. 配布用アーカイブのプライバシー情報と署名を確認し、Xcodeの配布検証とApp Store Connectの処理エラーを解消する。
4. スクリーンショット、必要なPCと外部サービスの説明、価格、年齢区分、データ収集の申告、暗号化申告、審査連絡先を登録する。
5. 初期状態の端末で審査用手順を最後まで試してから提出する。
